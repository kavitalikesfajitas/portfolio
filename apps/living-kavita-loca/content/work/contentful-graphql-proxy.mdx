# Contentful GraphQL Proxy

**Role:** Lead Engineer / Architect  
**Tech Stack:** TypeScript · Node.js · GraphQL · Redis · AWS

---

## Overview

I led design and implementation of a GraphQL proxy in front of Contentful to accelerate Product Detail Page (PDP) content at Nike scale. It gave PDP clients one place to fetch content and commerce signals, stayed steady through launch traffic, and shipped with observability so we could tune caching and upstream behavior from real production data—not guesswork.

## The Challenge

Contentful’s GraphQL API is capable, but calling it the same way you would for a small storefront does not hold up when PDP traffic spikes. We needed a dedicated layer that could:

- **Cut latency** on hot product content paths
- **Ride out launch spikes** without hammering upstream systems
- **Make cache and dependency behavior visible** in production
- **Keep content fresh** while still earning a high, safe cache hit rate

## Solution Architecture

### Caching Layer

I implemented a Redis-backed, multi-tier caching strategy with stale-while-revalidate behavior:

```typescript
interface CacheConfig {
  ttl: number;
  staleWhileRevalidate: boolean;
  keyPrefix: string;
}

async function getCachedContent<T>(
  key: string,
  fetcher: () => Promise<T>,
  config: CacheConfig,
): Promise<T> {
  const cached = await redis.get(key);

  if (cached && !isStale(cached, config.ttl)) {
    return JSON.parse(cached);
  }

  // Stale-while-revalidate pattern
  if (cached && config.staleWhileRevalidate) {
    revalidateInBackground(key, fetcher, config);
    return JSON.parse(cached);
  }

  return fetchAndCache(key, fetcher, config);
}
```

### Schema Stitching

The proxy stitched multiple GraphQL sources into a single contract for PDP consumers:

- **Contentful CMS** - Product copy, imagery, and merchandising content
- **Inventory Service** - Near-real-time availability and stock status
- **Pricing Service** - Dynamic pricing, promotions, and campaign logic

### Resilient Failover

The runtime was designed to degrade gracefully during dependency issues:

1. **Circuit breakers** isolate failing integrations and prevent cascade failures
2. **Fallback responses** serve cached content when upstream systems are unavailable
3. **Health-aware routing** routes traffic away from unhealthy nodes automatically

| -------------- | ------ | ----- | ----------------- |
| P50 Latency    | 180ms  | 45ms  | **75% faster**    |
| P95 Latency    | 420ms  | 168ms | **60% faster**    |
| Cache Hit Rate | N/A    | 94%   | -                 |
| Error Rate     | 0.8%   | 0.1%  | **87% reduction** |

These gains translated into faster PDP render times, more stable launch windows, and fewer production incidents tied to CMS content delivery.

## Key Learnings

- **Structured logging and tracing** are essential for diagnosing distributed cache behavior
- **Metrics-driven iteration** keeps optimization work aligned to measurable user impact
- **Progressive rollouts** surface edge cases early and reduce launch risk
